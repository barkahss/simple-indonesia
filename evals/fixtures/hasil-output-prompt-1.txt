Kode ini rapi dan modular, dependensinya sangat kecil, dan npm audit melaporkan nol kerentanan. Masalah utama ada di tiga tempat: kepatuhan hukum, identitas bot, dan ketahanan data. Riset dependensi dulu.
Dependensi langsung hanya dua: cheerio 1.2.0 dan playwright 1.63.0, keduanya versi terbaru di registry npm hari ini. Total pohon dependensi 23 paket. undici 7.30.0 ikut sebagai dependensi tidak langsung dari cheerio (versi terbaru 8.11.2), tetapi tanpa advisori keamanan yang diketahui. Runtime Anda Node 24.19.0, cocok untuk node:sqlite yang dipakai src/pipeline/penyimpanan.js (modul ini butuh Node 22.5 atau lebih baru). Syarat versi itu tidak ditulis di package.json, jadi tambahkan field engines. Playwright 1.63 mengunci Chromium 153.0.8010.12 di mesin saya, dan ini menjadi dasar temuan identitas di bawah.
Temuan paling serius adalah kepatuhan. docs/evaluasi.md menulis bahwa robots.txt Kompas melarang scraping secara eksplisit dan menyarankan modul Kompas dihentikan. Namun Kompas masih ada di src/config/portals.js:8. Hentikan modul itu, atau minta izin tertulis. Selain itu, kode tidak membaca robots.txt sama sekali. Tribunnews meminta Crawl-delay 10 detik, tetapi jeda antar permintaan detail hanya 0,3 sampai 1 detik di src/index.js:78.
Identitas bot juga tidak konsisten. User agent mengeras pada Chrome 141 di src/browser/pool.js:3, padahal Chromium yang terpasang versi 153. Ketidakcocokan dua belas versi ini adalah sinyal kuat untuk sistem anti-bot. Ambil versi dari browser.version() setelah peluncuran, lalu susun user agent secara dinamis. Retry juga memakai jeda tetap 1,5 detik tanpa backoff eksponensial (jeda yang memanjang pada tiap ulang) dan tanpa variasi acak, di src/browser/pool.js:40-53.
Ketahanan data punya tiga lubang. src/pipeline/simpan.js:25 menulis ulang berita.ndjson pada tiap eksekusi, jadi artikel dari eksekusi sebelumnya hilang dari berkas itu, walau masih tersimpan di SQLite. Berkas hasil-*.json menumpuk tanpa batas, sudah enam berkas dalam satu hari. Di sisi kualitas, suffix nama portal pada og:title belum dibersihkan, waktu terbit belum dinormalisasi ke ISO 8601, dan isi dipotong keras pada enam paragraf di src/extractors/artikel.js:108. Semua ini tercatat di evaluasi.md dan belum satu pun dikerjakan.
Sisi kuatnya nyata. Struktur browser, extractors, pipeline, dan config terpisah bersih. Galat diisolasi per portal sehingga satu kegagalan tidak menghentikan eksekusi. Pemblokiran gambar, font, dan CSS menghemat bandwidth. Fallback RSS bekerja untuk Tempo dan CNN Indonesia. Mode inkremental dengan SQLite sudah benar. Fungsi barengan di src/index.js:18 aman selama kerjakanPortal tidak melempar, dan saat ini memang tidak pernah melempar karena semua galat tertangkap.
Langkah selanjutnya dalam urutan prioritas. Pertama, hapus Kompas dari portals.js karena larangan tertulis di robots.txt. Kedua, susun user agent dinamis dari browser.version(). Ketiga, baca robots.txt sebelum permintaan pertama ke tiap domain dan hormati Crawl-delay, minimal untuk Tribunnews. Keempat, normalisasi waktu ke ISO 8601, bersihkan suffix judul, dan jadikan batas enam paragraf sebuah konfigurasi. Kelima, ubah berita.ndjson menjadi append atau bangun ulang dari SQLite, dan hapus berkas hasil-*.json lama secara otomatis. Keenam, tambahkan engines di package.json, .gitignore, dan README pendek. Ketujuh, tulis uji untuk daftarBerita, parseRss, dan ekstrakArtikel karena ketiganya fungsi murni yang mudah diuji dengan HTML statis.
